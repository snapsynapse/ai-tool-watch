# Reviewed publication
`node scripts/prepare-publication.js` is the only supported route from an accepted source/evidence update to a deployable `docs/` tree. It synchronizes canonical evidence, validates the changed source tree and talking-point claims, generates the site/API, validates generated structure, and checks one implementation fixture through the human implementation page, API export, and MCP server input.
It writes `docs/publication-manifest.json`, whose SHA-256 inventory identifies the exact artifact, its starting source revision, and `reviewed_input_sha256`: the full canonical `data/` tree, generator `scripts/`, and README consumed by the build. Operational run receipts are excluded because the site generator does not consume them. GitHub Pages and the PAICE FTP target both download and verify the `reviewed-publication` artifact into a fresh directory produced by the same workflow run. Required hidden files, including `.nojekyll` and `.well-known/security.txt`, are included. Preparation removes desktop metadata (`.DS_Store`, `Thumbs.db`, and AppleDouble sidecars) from generated output and excludes it from the reviewed-input digest; canonical source files are preserved. Neither target rebuilds from source. Both deployment jobs require the source revision, reviewed-input digest, and artifact digest passed independently from the preparation job. An internally valid artifact from another candidate is rejected. The verifier rejects missing or duplicate entries, unsafe paths, symlinks, malformed manifests, and mismatched inventories or hashes.
The workflow validates committed source/evidence before preparation, then stages `data/platforms/`, `data/watchlist/`, `data/evidence/index.json`, and `docs/` together when scheduled work produces a canonical update. A failed validator prevents artifact upload and therefore blocks both deployments. `node scripts/test-offline.js` runs the offline regression gate, explicitly excluding the separately invoked `smoke-live.test.js` network suite.
The preparation job records the source commit, source tree, reviewed-input SHA-256, and artifact SHA-256 in the workflow summary after any bot commit, so hosted evidence can tie a deployed artifact to its exact committed tree.
Hosted acceptance for PR #626 is recorded in `design/evidence/reviewed-publication-2026-09-07.json`: both deployment jobs verified one 181-file artifact, and the canonical live manifest plus 12 critical routes matched it. This does not establish stale-content remediation, direct-email delivery, or independent missed-run monitoring. GitHub's native failure-email canary is already evidenced separately and is not repeated here.

## Existing signals and silence
`evidence-alerts.yml` reports records older than its declared 30-day threshold through a deduplicated GitHub issue. It is a stale-evidence review signal, not a direct email or proof that a record changed. `verify-features.yml` retains review and failure evidence, writes its workflow summary, and explicitly reports direct notification and missed-run monitoring as `not_configured`.

The native GitHub failure-email canary has already been received and confirmed by Sam. It establishes that GitHub's account notification route can report a deliberately failed workflow; it does not configure a repository-owned notifier, fallback, or missed-run observer. Healthy no-change and valid-idle runs stay silent by design. T12 does not send or schedule another canary, and it does not close the separately scoped direct-email and independent-monitoring work.

## Deterministic regression coverage
The offline gate includes collector-level evidence evals using synthetic reviewed excerpts and the real product adapters. They exercise support, contradiction, hidden text, billing qualifiers, and abstention. An explicitly unassessed claim cannot become covered or renew freshness even if an adapter emits a matching value. These fixtures test evidence handling; they do not establish current provider facts or expand the live pilot's proven coverage.
Disposable publication correction fixtures exercise the real source synchronization, build, API, and MCP path. They check that deleting an unsupported entitlement does not change unrelated entitlements or verification dates, and that coverage notes and evidence provenance remain visible across surfaces.

## Post-deployment acceptance
The repository-owned live comparator is a separate network operation after deployment. It verifies the local artifact first, then compares the live manifest and 12 critical routes against its exact bytes. Run it from the repository with the accepted artifact in `docs/`:
Literal
```sh
node scripts/check-live-publication.js
```
Use `--artifact-dir` to select a downloaded workflow artifact and `--receipt` to save a new JSON receipt. Existing receipts are never overwritten. Exit 0 means every selected route matched, exit 1 means changed bytes or a missing route, and exit 2 means an inconclusive transport or invocation failure. Redirects are not followed; requests have time and byte limits. A matched report covers the selected routes and the manifest, not every deployed file or ongoing availability. The command is intentionally excluded from offline CI; its comparator and failure handling have deterministic tests with injected responses.
